`createRuntime` returns the runtime. Your server calls it from its routes: one call per chat message, approval decision or cron tick. Every method that takes a `principal` only ever sees that principal's data.

## handleChat

Runs one chat turn and streams the answer back. Return its `Response` straight from your route to `useChat`.

```ts
export async function POST(req: Request) {
  const principal = await requireUser(req);
  const { id, message, agent } = await req.json();
  return runtime.handleChat({ agent, chatId: id, principal, message, request: req });
}
```

## runAgent

Runs an agent to completion with no client attached: a webhook, a background job, a test. Returns the final answer.

## sendSignal

Tells a chat something from server code: an answer that arrived from elsewhere, a finished job, a message from a named person. By default the chat's agent answers it at once and the call resolves when that answer is finished; with `wake: false` it is only stored, and the agent reads it with the user's next message. See [the signals guide](/docs/guides/signals).

```ts
const sent = await runtime.sendSignal({
  chatId,
  principal,
  text: "The tax expert answered: file form 6B by 31 March.",
  from: { name: "Ann Lee", via: "expert console" },
  id: `reply:${replyId}`, // a retry stores it once
});
```

## listQueued, cancelQueued

What is held for a chat that was busy when it arrived, and taking one back before its turn starts. See [the queue guide](/docs/guides/queue). A message is held by `handleChat({ ifBusy: "queue" })`, a signal by `sendSignal` on a busy chat.

```ts
const waiting = await runtime.listQueued({ chatId, principal }); // AppMessage[], oldest first
const cancelled = await runtime.cancelQueued({ chatId, principal, id: waiting[0].id }); // false once its turn started
```

`listQueued` returns only what the user may see: a held signal sent without `visibility: "user"` is left out. `cancelQueued` takes any held id, so check it against `listQueued` before acting on an id from the browser, as the server's route does.

## pollChat

For a page with no stream open: whether an answer is running, what is held, and the history when it differs from what the page has.

```ts
const poll = await runtime.pollChat({ chatId, principal, cursor });
if (poll?.messages) render(poll.messages); // absent when nothing changed since `cursor`
```

## applyApproval

Continues a run that paused on a tool needing approval. Decisions that are no longer pending (a double click, an old tab) are ignored, so it is safe to call more than once.

```ts
return runtime.applyApproval({
  chatId,
  principal,
  decisions: [{ approvalId, approved: true }],
});
```

## schedule

Runs an agent on a timer, as the caller. Recurring schedules need `cron` in the runtime config, and a timer calling `runtime.cron()`.

```ts
await runtime.schedule({
  principal,
  agent: "brief",
  cron: "0 9 * * 1",
  timezone: "Europe/Helsinki",
  prompt: "Summarise last week's tickets.",
});
```

## cron

The one function to call on a timer, every minute or so. It fires due schedules and, with `durability` on, resumes interrupted runs. Safe to call from every server at once.

```ts
// app/api/cron/route.ts — called by your platform's cron every minute
export async function GET() {
  const { due, resumed, errors } = await runtime.cron();
  return Response.json({ fired: due.fired, resumed: resumed.length, errors });
}
```
