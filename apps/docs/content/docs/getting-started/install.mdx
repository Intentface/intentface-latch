The `@intentface/latch-*` packages publish to **GitHub Packages**, not the public npm registry. Two lines of config, then install normally.

## Registry access

Add an `.npmrc` at your project root:

```ini title=".npmrc"
@intentface:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

`GITHUB_TOKEN` needs the **`read:packages`** scope and nothing else — a classic PAT or a fine-grained token both work. Keep it in your environment, not in the file:

```bash
export GITHUB_TOKEN=ghp_…
```

<Callout type="warn" title="CI needs the token too">
The default `GITHUB_TOKEN` in GitHub Actions can read packages in the same organization. Elsewhere — Vercel, Fly, a Docker build — set `GITHUB_TOKEN` as a build-time secret, or installs fail with a `401` that looks like a missing package.
</Callout>

## What to install

Start with two packages. Everything else is additive, and nothing else is required.

```bash
pnpm add @intentface/latch-core @intentface/latch-drizzle ai @ai-sdk/anthropic
```

`ai` is a **peer dependency** (`>=7.0.0`) — core deliberately doesn't pin your AI SDK version. Its only runtime dependency is `zod`.

Add the rest as you need the capability:

| Package | Adds |
| --- | --- |
| `latch-server` | a mountable HTTP surface — see [Hosting](/docs/hosting) |
| `latch-mcp` | MCP connections, with an SSRF allowlist and vault-brokered auth |
| `latch-openapi` | connections from an OpenAPI spec |
| `latch-memory` | persistent agent memory across sessions |
| `latch-channels` | Slack, Telegram and WhatsApp |
| `latch-langfuse` | OpenTelemetry tracing, one trace per run |
| `latch-agent-builder` | agents defined as data, created from your UI |
| `latch-net` | SSRF blocklist and a rebinding-safe pinned `fetch` |

`latch-renderer` is not in this list on purpose: it's a headless-browser service
you deploy, not a package you install. See [Packages](/docs/reference/packages#latch-renderer).
